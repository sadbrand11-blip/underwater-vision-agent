# 第二步：模型如何选择下一步

`optical_agent/runtime.py` 中的 AgentRuntime 是手写循环：

1. 模型先用一次 JSON 调用解析任务类型与图片指向；程序生成不可修改的 TaskContract。
2. 将固定任务、工具说明、图像编号与已存在证据发给模型。
3. 模型提出工具名称和 JSON 参数；execute_tool 验证任务约束、参数并执行，返回 Observation。
4. 将结果发回模型。模型提出结束时，程序同时检查真实引用和固定完成条件。
5. 缺少或未选用必要证据时，明确反馈缺项；补齐后通过，否则标为任务未完成。

大模型没有收到图片像素，也不能自己执行 Python。检测器仍在本地显卡上工作。不同任务可以调用不同工具：只检查曝光时不检测目标；比较识别变化时需要两张图的质量和框。

## 如何防止模型编造测量结果

模型结束时只选择已经存在的证据编号和引用编号。程序读取真实结果生成报告。模型写入的额外分数、坐标、可靠性状态不会进入最终事实。这个第一版把解释限制为实际检测原因和检索片段，便于逐项核对。

没有任何依据的空对象或空列表不能有效结束。0.2.2 的 task_status=completed 表示最终报告满足程序固定的**已解析任务**，还不能证明模型正确理解了自由中文的原意。意图解析准确率需按独立预期任务评测。

任务所需证据尚未齐全时，请求使用 `tool_choice=required`；已有全部必要证据时使用 `auto`，可复用缓存后结束。旧曝光证据不会使检测任务跳过必要检测。任务理解请求不发送工具字段，沿用非思考模式和JSON输出。

## State 与 Context

State 是当前原图、校正图、检测结果等资源；Context 是发给模型的任务历史和观察结果。真实图片在 ToolContext 中，模型看到的是 original、corrected 这些引用。

会话追问会保留六轮任务及其最终引用。旧工具调用链不会被从中间截断；当前状态仍包含已算出的证据。会话闲置30分钟释放，重启服务会清空会话。

## 失败也是一个可见结果

未知工具或参数错误可返回给模型修正；每轮连续两次错误、模型10次、工具12次或180秒预算达到后停止。本地计算或HTTP调用返回后再检查时间预算，不强制杀死进程。HTTP的连接/读取等待timeout至多30秒，不能理解为整个请求必定30秒内结束。

缺密钥不会自动伪装成大模型回答。网页可明确选择“离线工具演示”，其 ScriptedClient 是规则调度，仅用于观察执行过程。

任务理解、结束格式、原生工具结构、引用错误与完成缺项共用每轮最多两次结果纠错，仍受原有预算限制。同批原生调用先整体验证，再开始执行，避免错误调用结构污染历史。未知工具、参数错误及无关工具经执行器拒绝，并作为工具观察反馈。

“刚才那张”绑定本轮开始时的图像状态；明确校正图而尚未校正时会提问。澄清问题与原请求保存在会话里，下一轮解析同时收到原请求和补充答复。任务开始后 LLM 无法改写契约。纯校正会交付 correction:original，包括实际候选图和处理参数；没有调整时保留 identity 原因。

CloudClient 返回上游 HTTP 状态、结束原因和逐次网络请求记录；LLMError 在失败时携带同样的结构化诊断。网络没有响应时状态为空，不推测HTTP码。运行日志记录脱敏后的响应片段，先脱敏再截断，禁止记录密钥、认证头或图片像素。网页的错误详情区分网络/账户/API失败、模型输出解析、工具执行和结束证据校验。

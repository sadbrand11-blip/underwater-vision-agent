# 0.5.1：简单长期记忆

## 为什么增加这一层

此前的 `Session` / `ToolContext` / `AdaptiveState` 是工作状态：图片、观察、缓存及最近几轮对话存在内存，闲置30分钟或服务重启后释放。执行日志不会自动成为记忆；RAG提供的是固定文献和项目知识。

现在增加两类长期记忆：**明确设置的使用偏好**和**程序生成的分析摘要**。它们不会训练或更新检测器、曝光算法和LLM权重。

## 你怎样使用

1. 双击原有启动文件，打开[对话工作台](http://127.0.0.1:7860/agent)。
2. 点击顶部[长期记忆与偏好](http://127.0.0.1:7860/memory)。保持“启用长期记忆与自动保存”勾选。
3. 如果希望默认关注管道，在类别列表按住Ctrl选择“管道”和“第二类管道”，点击“保存偏好”。不选类别表示全部当前支持类别。
4. 回到工作台，选择图片和“动态目标与规划”，提出“识别图中的目标”。未指定类别时，程序采用保存的默认类别。结果会显示本轮应用的偏好、历史参考和保存编号。
5. “只识别二维码”会覆盖管道偏好；“识别全部类别”会使用当前模型支持的全部类别；“只检查曝光”仍只评估曝光，不检测目标。
6. 在记忆页面搜索“管道”“校正”“质量失败”等词，查看摘要和真实指标。可删除单条或清空历史；清空历史保留偏好。

“简洁”默认折叠结果图片和执行过程，“展开”直接展示；测量值和结论内容相同。设置在每轮任务开始时读取，中途修改从下一轮生效。

关闭长期记忆后，不应用偏好、不参考历史、不保存新摘要；旧摘要仍可在页面查看或删除。**聊天中的“记住……”不会自动改写偏好**，第一版统一通过页面明确设置。旧调度对照只保存摘要，不改变类别或执行顺序。

## 记忆怎样流动

**任务开始 → 读取偏好快照 → 理解用户明确要求 → 程序合并未指定的默认类别 → 查找适用历史 → 模型规划与实际工具执行 → 完成校验 → 程序保存摘要。**

- 任务理解使用`target_scope=explicit/all/default`区分明确类别、明确全部和未指定；模型不填写默认类别，由程序应用。默认类别不在当前模型中或对应分支缺失时，先澄清。
- 历史先匹配任务、类别、模型权重、阈值/校准、视觉配置、算法代码和知识库版本，再使用字符2—4元组TF-IDF排序。最多3条、每条最多400字符；相似度不是正确概率。
- 历史在目标固定后才进入规划和行动上下文，标为非指令资料。原图、框坐标、完整聊天和密钥不会写入记忆数据库。
- `memory:...`编号与当前观察、图片和知识引用分离。不能填入`evidence_ids`、`citation_ids`，也不能当作重新规划的实际观察。
- 摘要仅使用最终报告选用的真实证据，包含质量指标、校正参数、候选数量及可靠性原因。不检测的任务不会补造数量；空检测不等于没有目标。质量失败可以是正确完成的分析，未完成、澄清和不支持任务不保存。
- 图片哈希、任务、版本和真实结果指纹用于去重；结果指纹包含真实框/分数，但只保存哈希，不保存框。同数量但不同结果不会误合并。

## 存储与故障

数据库：`D:\CodexData\optical_agent\memory\memory.sqlite3`。SQLite的`-wal`、`-shm`文件也位于同一目录；保留最近200条不同摘要，偏好持续保存。每个操作使用事务并关闭连接，忙等待上限2秒。

数据库读取、写入失败或版本不支持时显示“记忆不可用”，当前视觉任务继续执行。不会自动清空或重建损坏数据库。历史是查看和规划资料，**不能恢复已过期的图片会话**。

第一版是单用户本地功能。开启云端对话时，最多3条相关摘要会与现有任务状态一起发送给云端；图片仍留在本地。关闭记忆可以停止后续发送摘要。保存和检索本身不新增LLM请求。

## 接口与兼容

| 接口 | 用途 |
|---|---|
| `GET/PUT /api/memory/preferences` | 获取/完整更新`enabled`、`target_classes`、`display_detail` |
| `GET /api/memory/history?q=...` | 查看或搜索摘要；查询最多400字符 |
| `DELETE /api/memory/history/<memory_id>` | 删除单条 |
| `DELETE /api/memory/history` | 清空摘要，保留偏好 |
| `/api/chat`新增`memory_context` | 偏好、实际提供的历史参考、保存状态及故障提示 |

沿用本地Host/Origin检查。网页默认启用；直接构造`AgentRuntime`/`AdaptiveRuntime`时默认关闭，需要显式传入`memory_store`。原评测入口不读取个人数据库。历史不加入固定RAG索引，0.5.0检索成绩和旧视觉/正式Agent Eval报告保留。

## 离线演示与验证

运行`python -m optical_agent.experiments demo_memory --output-dir D:\CodexData\optical_agent\memory\runs\my_demo`。它启动两个实际Python进程，使用既有SODD测试索引6、7及现有检测器，离线规则调度。第二个进程读取偏好/历史，同时重新检测另一张图片。输出目录必须是D盘memory内的新子目录；不会覆盖已有演示或修改个人记忆。

查看[本轮检查结果](reports/MEMORY_RESULTS.md)。这个演示验证工程机制，不验证真实LLM使用历史的质量，也没有测量识别精度改善。

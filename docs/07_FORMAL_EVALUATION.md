# 正式Agent Eval：怎样验证一个Agent完成了任务

正式评测用20条事先保留的任务，每条重复3次，共60次案例运行、78轮问题。多轮问题共享该案例的图片状态，每次案例都创建独立会话。

## 1. 本次优化的思路

评测程序增加四个保障：

- **固定题目和条件**：预设标签供独立评分使用，模型只收到用户问题。程序自校验通过，不代表模型理解对了用户意图。
- **固定被测版本**：冻结代码、提示、工具说明、图片和标注、权重与校准、质量配置、知识库和请求配置。继续运行时发现变化即停止。
- **保留所有尝试**：请求前计数，重试也计入；案例开始前、每轮完成后立即保存。失败案例和中断案例不会被成功复测覆盖。
- **分开报告结果**：`evaluation_status`表示是否完整；`acceptance_status`表示是否达标。评测完整也可能不通过。

正式通过要求：完整运行20题×3；按轮工具路线/必要证据符合≥90%，参数规则正确≥95%，预设oracle案例流程符合≥85%；未注册工具实际执行、可靠性越权、事实或原图违反均为0。此oracle未核对指定类别筛选，不能代表完整语义满足率。

| 文件 | 用途 |

## 3. 一次可观察的学习示例

找到比较或校正图追问的记录，依次看：

1. `message`：用户实际提出的问题。
2. `expected`：联网前预设的正确任务、图片、证据及工具范围，未发送给模型。
3. `result.task_contract`：模型实际理解的任务及程序固定的完成条件。
4. `result.trace`：Action是工具和参数；Observation是实际执行结果；`cached`表示本会话缓存。
5. `score`：独立评分。即使`task_validation.passed=true`，意图或图片指向错误仍判为失败。

例如“识别校正后的图”，原图检测证据不能代替`detections:corrected`；没有校正图时正确澄清，可以满足该轮预设要求。

### 本次真实记录的两个例子

- **hold_03第2轮：恢复成功。**理解为纯校正 → 评估原图 → 输出identity候选与参数（无需调整）→ 模型在JSON后追加文字 → 格式验证器要求纠正 → 返回有效JSON → 预设oracle通过。共5次模型请求、2次工具调用、1次格式修复。
- **hold_06第3轮：最终失败。**问题“在原图中找二维码和管道，给候选框。”被解析为unsupported，没有检测。独立标签要求detection＋原图检测证据，因此判失败。对应本次唯一最终案例失败。

审核还发现，hold_13要求二维码却返回pipe仍通过，说明当前标签只检查粗粒度流程，遗漏类别语义。报告明确保留这个问题。

## 4. 命令入口

在项目目录打开终端。以下预检不发送云端请求，也不生成正式验收成绩：

```powershell
python -m optical_agent.experiments evaluate_orchestration --mode formal --backend live --vision sodd --preflight --run-id formal-20260930-v023 --max-http-attempts 600
```

正式运行会产生付费API调用。默认上限仍为120，本次已明确授权600次：

```powershell
python -m optical_agent.experiments evaluate_orchestration --mode formal --backend live --vision sodd --run-id formal-20260930-v023 --max-http-attempts 600
```

中断后，在冻结内容未变化时，追加`--resume`。程序跳过已完成或失败记录，保留中断案例为失败，只继续未开始案例。不能以同一编号重跑挑选最佳成绩。认证、余额错误和损坏进度停止批次。

读取已有记录生成公开报告，无API调用：

```powershell
python -m optical_agent.experiments summarize_formal_eval formal-20260930-v023
```

报告生成器先核对冻结文件、图片与标注、账本、逐轮题目和标签，再重放已保存的检测观察，重新计算质量、评分与GT框匹配。不会重新执行神经网络或发送云端请求。损坏记录拒绝发布。

本次结果冻结于提交`4b9ebb7`，待测Agent行为为0.2.3；0.2.4在结果出齐后完善报告核对和说明。升级后直接恢复旧冻结运行会因版本变化被拒绝；旧记录仍可用报告生成器核验，重跑须使用冻结版本且标明复测。

旧开发评测命令继续可用。正式模式不接受模拟视觉工具、部分题目或减少重复次数。

## 5. 如何解释成绩

20条预设任务尚未经过外部人工复核，三次重复用于观察稳定性，不等于60条独立任务。正式评测期间不根据保留题调整提示；以后用这些题复测要明确标注。

真实视觉精度按实际执行检测的来源另行统计，重复和缓存去重；不同任务检测的图像集合不同。调度成绩不能证明识别精度或曝光校正收益提高，也不能证明跨水域泛化。

语义审计由另一个同模型家族的审核Agent完成，注明暂定意见；程序验收条件独立计算。

# 0.6.0 通用自然图像视觉评测

本报告记录**官方预训练检测器的本地视觉基准**。没有重新训练模型，也没有付费 API 请求；不将检测成绩解释为真实 LLM 调度成功率、任意领域泛化能力或增强带来的准确率提升。

## 数据与测试范围

| 集合 | 原图数 | 非crowd目标数 | 用途 |
|---|---:|---:|---|
| 开发 | 3,000 | 21,578 | 校正候选策略比较 |
| 校准 | 1,000 | 7,309 | 逐类阈值与经验分桶 |
| 保留测试 | 1,000 | 7,448 | 冻结后唯一一次测试 |

数据来自 COCO val2017，共5,000张、80类、36,781个标注（含446个crowd）。全部通过解码、尺寸及框坐标检查，0张隔离。按像素SHA256和pHash（距离≤4）检查后未发现链接重复，形成5,000组，种子为 `20261023`，按组60/20/20划分。缺少原始拍摄序列，因此不能保证真正的场景独立；公开验证集也不等于模型从未见过的数据。

每个集合另按固定哈希取30张诊断原图，比较原样、亮度×0.6、亮度×1.4、横向0.6—1.4亮度变化，以及原样/Gamma/有界局部校正三个方法。测试的360条变体结果来自30张基础图，不能视为360张独立图，模拟亮度变化也不等于真实重拍。

## 保留测试结果

模型为完整官方91槽检测头的 Faster R-CNN MobileNetV3 320，保留80个有效COCO类别编号。mAP由官方 `pycocotools.COCOeval==2.0.10` 计算，原始预测分数下限0.05；工作点使用同类别IoU0.5、分数降序的一对一匹配，重复框计误报，crowd区域按覆盖关系忽略。

| 指标 | 固定0.35阈值 | 冻结逐类工作点 |
|---|---:|---:|
| 微平均召回 | 36.36% | 33.55% |
| 宏平均召回 | 38.32% | 36.85% |
| 误报/图 | 1.525 | 1.086 |
| TP / FP / FN | 2,708 / 1,525 / 4,740 | 2,499 / 1,086 / 4,949 |

原始分数排序下的 **COCO AP@[.50:.95]为24.12%，AP50为39.46%，AP75为24.99%**。这些AP指标与表中的工作阈值指标含义不同。逐类工作点减少误报，同时降低召回；不能把该取舍描述成所有指标都改善。

本机RTX3060 Laptop上，实验单图处理平均110.29ms、P95为132.98ms。计时包括读图、质量测量与推理，到缓存写入之前，可能包含冷启动及其他本地验证影响；它不是云端LLM端到端延迟或实时保证。

## 校准与校正限制

校准仅使用1,000张校准原图。每类至少30个GT、10张正样本图、30个预测，并需要至少两个有效分数桶；在经验精度≥80%约束下选择最大召回的阈值，不足时保留0.35并标记不足。

- **22/80类满足校准集工程条件，58类不足。** 该状态不是“22类已通过保留测试精度验收”。
- 这22类在测试集的合计TP为1,612、FP为377，合计精度81.05%；但**10/22类单类测试精度低于80%**。不能宣称逐类精度保证，也未据此再次调整阈值。
- 经验分数桶不等于逐框正确概率。原图校准不自动适用于增强图，当前图像的质量、检测稳定性与校准适用范围仍需分别检查。
- 两种有界校正均未通过预先约定的开发收益门槛，因此默认选择 **原图**；显式生成候选与比较功能保留。未证明校正能提高本版检测精度。

## 冻结与审查记录

这些验证与上面的带标注视觉精度分开计分。本轮没有调用真实LLM，不给出新的目标理解率、token费用或正式Agent成功率。

干净入口验证调用实际run_demo.main，只在进程内将记忆存储重定向至验证数据库，避免写用户历史。公开整套3项跳过为缺可选pycocotools、Windows符号链接权限、公开历史不包含私有旧提交；不把跳过计为通过。

三条离线路径使用同一句“检查这张图，必要时校正曝光，然后只识别人，说明结果是否可靠”：

| 输入 | 动态实际行动 | 动态检测计算 | 固定完整流程检测计算 |
|---|---|---:|---:|
| NASA原始照片 | 质量→检测→单帧内部规则检查，采用原图 | 1 | 2 |
| 亮度×0.45（模拟） | 按开发策略保留原图，再检测与检查 | 1 | 2 |
| 全黑（模拟） | 质量→质量失败说明，停止检测与恢复 | 0 | 1 |

两种运行器的目标、工具参数、证据、采用图、状态和预算一致；图节点轨迹允许不同。原始照片也会触发“偏暗”启发式提示，不能把文件名normal解释成曝光真值。固定流程会生成候选并比较，最终同样采用原图。这里仅演示实际行动差异，非公平延迟基准，也不代表动态LLM优于Workflow。原图及×0.45输入的`reliable`只表示当前单帧内部规则通过，既无跨曝光一致性，也没有这张示例的目标标注或现场精度保证。

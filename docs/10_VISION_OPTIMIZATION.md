# 0.4.0 视觉实验：操作与优化思路

## 你怎样使用

双击项目目录的 `双击启动.bat`，打开 http://127.0.0.1:7860/agent 。

1. 在“视觉配置”中选择现有默认模型、实验重训对照或实验改进候选。
2. 上传一张图片并创建会话。切换视觉配置后应重新创建会话。
3. 本轮选择“离线工具演示”，可输入“只检查曝光”“只识别管道”“只识别水下机器人”或“必要时校正，然后只识别水下机器人，并说明是否可靠”。
4. 查看真实质量指标、框图、模型来源、校准状态和执行记录。
5. 对同一图片分别建立会话比较新旧配置。机器人在两个实验配置中使用同一个独立模型，没有 AUV/ROV 细分类。

实验配置需要“动态目标与规划”；旧调度对照使用现有默认模型。实验多分支配置本轮仅接受单张原图及其候选。旧默认网页的多帧入口会检查所有质量有效帧，有效帧检测冲突时不能只取可靠帧宣称一致。

离线演示的调度使用规则，视觉计算使用真实模型；它不能证明 LLM 理解或规划能力。云端对话入口仍可使用已有配置，本轮没有调用付费 LLM。

## 为什么这样优化

**先检查数据，再选择参数，最后测保留测试集。** 同一图、其参考增强图、近重复图和模拟曝光版本必须在同一组。UIEB 与 UIIS10K 之间的重叠也参加分组。

UIEB 用来衡量曝光校正与作者参考增强图的一致性。参考图不是相机曝光真值，PSNR/SSIM 不等于检测准确率。当前算法只做有界亮度、局部对比度和条件降噪，不解决全部水下色偏、散射和去模糊问题。

24 组参数在 UIEB 训练组搜索，仅前三组进入验证。验证同时检查参考指标、饱和/暗部变化及 SODD 检测证据。所有配对指标使用一致的 RGB 8 位输入，将长边最多缩到 **768 像素**；结果属于本项目的缩放评测，不能直接比较论文的原分辨率成绩。检测器使用 TorchVision 原有 320 尺寸变换。

六类设施检测分别训练旧增强策略对照和新增强策略候选，使用相同 COCO 初始化、种子、划分、学习率和停止条件。机器人单独训练，因为 SODD 没有机器人标注，UIIS10K 也不完整标注 SODD 六类。把两者直接混成七类会产生错误背景监督。

当前六类 SODD 保持：螺旋桨、两种管道、红鳍片、网、二维码。UIIS10K 官方 robots 类映射为 `underwater_robot`，全局类别编号为 7。该类别包含多种水下机器人，不推断型号或用途。

## 复现顺序

在项目目录运行；使用已安装的本地 Python/CUDA 环境。

```powershell
python download_vision_data.py
python prepare_vision_data.py
python prepare_vision_data.py --quarantine-invalid
python evaluate_vision_exposure.py search
python train_vision_detectors.py
python evaluate_vision_exposure.py select
python reconcile_vision_calibration.py
python evaluate_vision_detectors.py
python evaluate_vision_exposure.py test
python report_vision.py
```

已有完整模型和逐图缓存会复用。已开始的模型不会无记录地覆盖；已有测试冻结后禁止改变校准和数据。重新开展实验应使用新版本目录和运行编号，不能删除失败记录只留最好结果。

上面是入口顺序，不是本次失败与恢复的逐位重放。设施模型实际使用的训练源码另存于 `vision_v040/training_source_before_calibration_revalidation.py`。机器人最后恢复在冻结前使用以下命令，从已保留的重试第2轮最佳权重继续；不应在当前冻结目录覆盖执行：

```powershell
python train_vision_detectors.py --branch robot --strategy improved --epochs 4 --resume D:\CodexData\optical_agent\vision_v040\models\aborted_empty_roi_robot_improved.pt
```

第一次增强策略试跑和中间重试的完整源码快照没有全部保留，不能保证逐位重放这两次失败。其权重、历史与日志均保留；初始中止历史和部分权重内嵌状态仍写着 `running`，最终完成以侧边历史、校准文件和对应哈希为依据。补充说明不改写原始文件。

本次在扩大到全部 COCO 类别检查时，隔离了一张含两个非机器人空框的校准负样本。其原文件、原清单和检查记录保留；训练/选模清单完全相同。校准修订在测试之前执行并记录。第一次增强幅度未正确复现旧策略的训练试跑也已保留为中止试跑，不进入对照成绩。

机器人初次训练第4轮出现非有限损失；加入有限检查后的同种子重试也在第4轮停止。日志定位到纯负样本批次的RoI分类和回归损失，而RPN损失有限。控制实验可复现“没有候选区域时损失非有限”；原失败时的即时权重未保存，因此不是原失败的逐位重放。

最终恢复时仅训练阶段令机器人RPN保留低分候选，验证/推理仍用原0.05阈值，避免纯负样本批次没有可学习区域。从验证选中的恢复权重继续最多4轮，重置AdamW并记录权重来源；两次4轮尝试加恢复4轮合计不超过12。此处是同种子的错误恢复，不是多个独立种子实验。最多两批数值异常允许记录并跳过，超出立即停止。

## 怎样读成绩

结果见 [视觉实验报告](../VISION_RESULTS.md)。先看采用门槛，再看逐类召回、误报和拒识。验证通过不自动代表测试有效，更不代表可靠部署。

机器人框分数不是导航安全概率。校准不足时框只能是候选；全黑、全白或严重信息丢失仍输出质量失败。没有跨曝光帧时，可靠性属于单帧内部规则检查，不是多帧一致性验证。

本次保留测试：新曝光参数SSIM略低于旧算法；六类候选召回上升，但误报和单类退化未通过采用门槛，因此保持旧默认。机器人原图召回66.67%，候选精确率3.51%；自动接受结果精确率30.95%，不能称为可靠航行器识别。校准曲线按每个分支跨类合并拟合，样本少且只使用原图，没有逐类或校正图概率保证。

## 一次实际网页调用

使用 `D:\CodexData\optical_agent\uiis10k\data\UIIS10K\img\test_0352.jpg`，选择“实验改进候选＋机器人”和离线动态调度，提出“检查这张水下图，必要时校正曝光，然后只识别水下机器人，说明结果是否可靠”。

真实观察提示偏暗，亮度中位数约0.106。规则调度执行质量评估、Gamma候选、原图和候选检测及比较；亮度约升至0.153，候选数3→3，但检测不一致，结果为不可靠。实际视觉计算来自本地模型，调度是规则演示，不能作为真实LLM规划证据。

**这条网页路径使用Gamma，不含CLAHE；报告中的端到端校正表使用完整局部校正。** 配置名相同不表示执行方法相同，应查看工具记录和参数。模型不存在显示不可用；会话内换模型会停止旧缓存复用，要求新建会话。

修订入口标识为 `v040_delivery_r1`。九个冻结核心源码及单帧实验结果未改写；交付保护在独立模块中实现，完整核验见 [VISION_VERIFICATION.json](../VISION_VERIFICATION.json)。MOUD诊断图和部分依赖没有进入原预冻结清单，后补出处记录也不声称它们曾预冻结。

旧 0.2.4 正式 Agent Eval 和 0.3.0 动态调度报告保持原样。本轮是一次固定种子的视觉实验，不能据此宣布新的 Agent 正式验收完成。

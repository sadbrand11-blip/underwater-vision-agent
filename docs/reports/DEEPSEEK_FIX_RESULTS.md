# DeepSeek 调度与错误详情修复（0.2.1）

## 问题与改动

早期失败记录出现一次模型响应、零次图像工具执行，随后结束格式或证据校验失败。原始回复未记录，不能确定当时具体返回了哪种无效格式。该问题间歇出现；诊断期间原有请求也能正常调用工具。

本版在没有实际依据时要求原生工具调用；已有依据时允许选择结果结束。结束格式、调用结构或引用错误最多纠正两次，原有调用与时间预算继续生效。曝光数值、质量状态和检测可靠性仍来源于现有视觉工具，新增回复不能覆盖它们。

错误详情保留上游HTTP状态、失败阶段、结束原因、请求编号和脱敏的模型返回片段。连接失败不生成虚构HTTP码；401、403、402不重试，网络/429/5xx最多重试一次。先脱敏再截断，日志不包含密钥、认证头或图像像素。

## 验证

- Python自动检查：48项通过，包含提前结束恢复、JSON/引用纠错、纠错与调用上限、原图保护与缓存、错误码、日志脱敏和网页接口。
- 前端渲染检查：使用本地模拟响应验证401、402、HTTP 200后结束校验失败及没有HTTP响应四种情况；错误详情默认展开，返回片段按普通文本显示。
- 真实接口诊断在修改前完成：三次获准的项目请求均HTTP 200；先要求曝光工具，再传入本地实际测量，结束引用通过报告校验。这不是大规模云端能力评测。
- 修复代码使用上述工具调用与结束回复进行离线回放；调用编号替换为固定测试编号，不保存原始请求或密钥。本次实施未新增付费云端请求。
- D盘默认示例图（1920×1080）的修复后回放完成：首轮`required`，后续`auto`；只执行一次曝光工具，质量结果与原流程一致，原图保持一致，检测器未调用；缓存追问无需再次计算。暗像素占比0.156%，高亮像素占比0.392%。

复现命令：

```powershell
python -m unittest discover -s tests -v
node tests/check_conversation_ui.cjs
```

前端检查需要Node，仅用于开发测试，不是运行网页的额外依赖。回放文件为 `tests/fixtures/deepseek_quality_responses.json`。

## 使用和边界

打开工作台后重新加载图片，选择真实大模型对话，再提交任务。发生错误时，先看原图上方的“错误详情”，再展开“查看执行过程”。本地 `/api/chat` 返回200与上游模型返回200是两个不同状态。

新增API字段包括 `request_attempts`、`model_request_attempts`、`format_repairs`、`error_details`、`last_model_diagnostics`；原有 `model_calls` 表示成功解析的模型响应次数。网络重试计入请求尝试；格式纠错计入模型调度预算。已有返回字段和上传入口继续使用。

这次验证覆盖曝光任务和错误恢复，没有重新训练视觉模型，也没有执行50条任务的完整真实云端评测。质量“通过”仍表示通过当前工程阈值，不能等同于水下图像没有雾化、色偏或所有目标均可识别。API故障或模型持续返回无效结果仍会被如实报告。

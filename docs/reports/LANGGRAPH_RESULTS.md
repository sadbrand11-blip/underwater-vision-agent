真实 `StateGraph` 已作为可选运行器接入网页，默认仍为 native。7个演示案例、14次运行的核心结果全部一致；新测试另覆盖8组任务序列的逐轮对照、故障与记忆约束。当前 native 调度文件未修改。

- 完整回归：**237项Python测试通过**，保留1条既有Transformers弃用警告。
- 网页夹具检查：**22项通过**；实际网页另检查LangGraph曝光任务及节点记录。
- 未安装LangGraph的基础环境：native检查通过，38项图专用测试明确跳过。
- **上游API请求0**；离线模型回复为规则或预设回复，不声称验证真实LLM能力。

## 怎样判断“等价”

两个运行器使用独立会话、相同输入和确定性的模型回复。比较目标契约、必要证据、采用图片、实际质量指标、目标框与数量、可靠性结论、工具名称和参数、计算次数、预算与纠错计数。排除会话编号和耗时；未执行动作不能计入完成。

测试发现模型请求中的工具观察也包含耗时。初次全量运行因此出现1项请求对照失败（其余236项通过）。修正对照程序，仅从结构化结果及序列化请求中排除耗时字段，其他字段仍严格比较；最终237项通过。初始失败日志与最终日志均保留于D盘。

## 纠错示例

`理解目标 → 生成计划 → 提前提交曝光证据 → 完成校验失败 → 纠错 → 选择行动 → 实际曝光评估 → 选择行动 → 校验通过 → 输出结果`。

该例用了5次模型阶段调用、1次工具调用、1次纠错。第一次提交的证据尚不存在，不能通过验证；真实工具执行后才能完成。回复是预设的，验证的是图执行与证据规则。

## 测试范围与限制

- 既有动态调度和记忆测试在LangGraph上复用，并加入独立核心结果对照。
- 覆盖目标过滤、候选下降后重新规划、多轮图片绑定、缓存、虚构证据、格式错误、调用预算、API错误计数、图步骤停止、节点异常释放锁及记忆不重复保存。
- API依赖延迟导入，native缺省行为保留；运行器切换需要独立图片会话。
- 本轮使用现有SODD权重，未训练视觉模型、未修改RAG发布配置、未重跑旧正式Agent Eval。
- SODD偏暗与全黑图是模拟扰动，不代表相机重拍。每轮耗时见机器可读摘要，包含不同任务、夹具与真实视觉，未混合计算成延迟基准。
- 本次证明离线工程行为等价，不能据此宣称识别精度提高或新的正式验收通过。

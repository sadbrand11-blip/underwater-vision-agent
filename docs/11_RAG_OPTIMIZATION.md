# 第一步怎么使用0.5.0知识检索

## 打开对照页面

双击原来的“启动”文件，在对话工作台顶部点击 **知识检索对照**。也可直接打开 <http://127.0.0.1:7860/knowledge>。

不用上传图片、不需要DeepSeek密钥。输入：

> 为什么机器人检测框变多，仍不能说识别更准确？

选择“实验机器人＋设施候选”，点击“对比检索”。三列展示实际返回片段、出处、资料类型、不同分数与时间。TF-IDF比较词语，Embedding比较本地模型向量，Hybrid融合两种排名。数字不是正确概率。

资料中0.4.0机器人误报的结论是**本项目实测**；论文对增强与任务表现的解释是**通用研究**。论文的方法尚未接入本项目。若阈值拒绝返回，页面如实显示；若模型或索引缺失，显示“不可用”，两种情况不同。

## 在图像Agent里使用

创建图片会话前，知识检索保持“发布默认”，使用本轮达到门槛的Hybrid。可切换旧TF-IDF、结构化TF-IDF或Embedding来对照；创建后这个会话固定知识库版本、检索方式和视觉配置。修改下拉框后须创建新会话。

图像工具的测量、框和可靠性规则没有改变。检索只为解释提供出处，不能把质量失败改成可靠。旧默认只有SODD六类设施，机器人仍属于实验视觉分支。

## 优化思路

1. 保存旧8份资料和55个片段，作为C0；不因更新README而改变基线。
2. 将旧资料按段落、句子和完整表格行分段，形成C0_struct：96片段，并过滤不适用版本。
3. 加入六份核实的中文研究卡，形成C1：126片段。卡片注明条件、限制与项目解释。
4. 先写100道带原句位置的题目，独立审核，修正遗漏等价证据；再冻结。
5. 开发集选阈值和候选，保留集只验收。未过滤排序和实际交付结果分别统计，避免把拒绝策略误说成全面排序提升。

本轮C1保留集：TF-IDF实际Recall@3为35%，Embedding为45%，Hybrid为47.5%；Hybrid对照增益12.5个百分点，MRR@10为0.4875，无答案返回0/10，CPU热查询P95约26ms。相同旧问题对照：Hybrid从C0的25%提升到C1的43.3%；这个提升同时包含结构化分段、版本过滤和开发阈值校准。单独加六份知识卡没有提高旧题Recall@3，但提供新文献题的可答证据。

47.5%说明仍有大量缺项；不是正式问答质量验收，也不是识别精度提高。详见 [实验报告](../RAG_RESULTS.md) 和 [逐题失败表](../RAG_CASES.csv)。

## 第一次下载项目后的准备

本机已准备好。不必重新下载。另一台电脑需要完整Git历史，并安装项目依赖；模型、原文及索引继续只写到D盘。

```powershell
python prepare_rag.py --assets all
python evaluate_rag.py snapshot
python evaluate_rag.py prepare
python app.py
```

`snapshot`从固定旧提交重建C0，将六张已核实知识卡加入C1；已有快照禁止覆盖。若Git历史不含该提交，应先取得完整项目历史，不能用最新README冒充旧基线。

索引坏了不会默默重建。确认D盘下索引对应的语料/模型指纹目录后，先将该目录改名备份，再运行`prepare`。不要改已冻结实验的文件；新实验使用新的运行编号。

```powershell
python evaluate_rag.py freeze --run-id my_rag_replication
python evaluate_rag.py dev --run-id my_rag_replication
python evaluate_rag.py test --run-id my_rag_replication
```

没有调用云端模型。原始脱敏记录在 `D:\CodexData\optical_agent\rag\runs`；仓库只公开代码、标签、研究卡与必要摘要。
